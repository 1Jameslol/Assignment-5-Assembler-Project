Parts 1 and 2

============================================================
PART 1: ASSEMBLE INSTRUCTIONS BY HAND
============================================================

MIPS register numbers used:

    $zero = register 0  = 00000
    $t0   = register 8  = 01000
    $t1   = register 9  = 01001
    $t2   = register 10 = 01010
    $t3   = register 11 = 01011

------------------------------------------------------------
1. addi $t0, $zero, 3
------------------------------------------------------------

Format: I-type

I-type fields:

    opcode | rs    | rt    | immediate
    6 bits | 5 bits| 5 bits| 16 bits

    opcode    = addi = 8  = 001000
    rs        = $zero     = 0  = 00000
    rt        = $t0       = 8  = 01000
    immediate = 3          = 0000000000000011

Putting the fields together:

    001000 00000 01000 0000000000000011

32-bit machine code:

    00100000000010000000000000000011

------------------------------------------------------------
2. addi $t1, $zero, 5
------------------------------------------------------------

Format: I-type

    opcode    = addi = 8  = 001000
    rs        = $zero     = 0  = 00000
    rt        = $t1       = 9  = 01001
    immediate = 5          = 0000000000000101

Putting the fields together:

    001000 00000 01001 0000000000000101

32-bit machine code:

    00100000000010010000000000000101

------------------------------------------------------------
3. add $t2, $t0, $t1
------------------------------------------------------------

Format: R-type

R-type fields:

    opcode | rs    | rt    | rd    | shamt | funct
    6 bits | 5 bits| 5 bits| 5 bits| 5 bits| 6 bits

    opcode = 0       = 000000
    rs     = $t0     = 8  = 01000
    rt     = $t1     = 9  = 01001
    rd     = $t2     = 10 = 01010
    shamt  = 0       = 00000
    funct  = add = 32 = 100000

Putting the fields together:

    000000 01000 01001 01010 00000 100000

32-bit machine code:

    00000001000010010101000000100000

------------------------------------------------------------
4. sub $t3, $t1, $t0
------------------------------------------------------------

Format: R-type

    opcode = 0       = 000000
    rs     = $t1     = 9  = 01001
    rt     = $t0     = 8  = 01000
    rd     = $t3     = 11 = 01011
    shamt  = 0       = 00000
    funct  = sub = 34 = 100010

Putting the fields together:

    000000 01001 01000 01011 00000 100010

32-bit machine code:

    00000001001010000101100000100010


============================================================
PART 2: REPRESENT MACHINE CODE AS BINARY BYTES
============================================================

Each 32-bit instruction is divided into four groups of eight bits.

1. addi $t0, $zero, 3

    32-bit binary: 00100000000010000000000000000011
    Four bytes:    00100000 00001000 00000000 00000011
    Hexadecimal:   0x20     0x08     0x00     0x03
    Combined hex:  20 08 00 03

2. addi $t1, $zero, 5

    32-bit binary: 00100000000010010000000000000101
    Four bytes:    00100000 00001001 00000000 00000101
    Hexadecimal:   0x20     0x09     0x00     0x05
    Combined hex:  20 09 00 05

3. add $t2, $t0, $t1

    32-bit binary: 00000001000010010101000000100000
    Four bytes:    00000001 00001001 01010000 00100000
    Hexadecimal:   0x01     0x09     0x50     0x20
    Combined hex:  01 09 50 20

4. sub $t3, $t1, $t0

    32-bit binary: 00000001001010000101100000100010
    Four bytes:    00000001 00101000 01011000 00100010
    Hexadecimal:   0x01     0x28     0x58     0x22
    Combined hex:  01 28 58 22


============================================================
ASCII MACHINE CODE VERSUS BINARY MACHINE CODE
============================================================

mhc-ascii:

    This is a text file containing readable characters: 0 and 1.
    One 32-bit instruction is represented by 32 text characters,
    not counting spaces or line breaks.

    Example:

    00100000000010000000000000000011

    This file is easy for a person to open and read, but each 0 or 1
    is stored as a full text character. Therefore, one instruction
    uses at least 32 text bytes before metadata and line endings.

mhc-bin:

    This is a binary file containing the actual machine-code bytes.
    One 32-bit instruction requires exactly four bytes.

    For addi $t0, $zero, 3, the actual bytes are:

    00100000 00001000 00000000 00000011

    In hexadecimal, those bytes are:

    20 08 00 03

The two formats represent the same instruction, but they store it
differently. mhc-ascii stores readable digit characters, while mhc-bin
stores the four actual byte values. The assembler project uses metadata
to preserve the separation between the instruction section and data
section.
